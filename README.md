# 墨愚 · 品牌官网

前端使用原生 HTML / CSS / JavaScript，无构建步骤；账号功能使用 Node.js + SQLite + Nodemailer 服务端。项目位于 Zhanghao 用户目录下的 moyu 文件夹，不修改 Eudaimonia 项目。

## 本地预览

需要 Node.js 22.16+（当前已用 25.2.1 验证）。在项目目录安装依赖后使用 `npm start`，访问 http://127.0.0.1:4175 。不要再用 Python 静态服务器运行账号功能；只上传静态页面也无法完成邮箱验证。

### 邮件服务配置（真实收件的必要条件）

- 参考 .env.example，在本机创建未提交的 .env，填写 SMTP_HOST、SMTP_PORT、SMTP_SECURE、SMTP_USER、SMTP_PASS、SMTP_FROM，然后重启服务。
- 465 端口使用 SMTP_SECURE=true；587 使用 false 并强制 STARTTLS。不关闭证书校验。
- 配置值来自你选用的发件邮箱或邮件服务商；授权码/密码只填写在本机环境文件或部署平台的环境变量中，不发到聊天，不写入前端。首次上线需验证服务商授权与收件箱/垃圾邮件实际投递。
- 未配置 SMTP 时服务返回 503、页面说明注册暂不可用；邮件发送失败返回 502，不显示「已发送」。目前并未配置真实发件凭据，自动化测试使用注入的测试邮件接收器，不能证明真实投递成功。
- 公开部署需 Node 运行环境和持久化磁盘，设置 PUBLIC_ORIGIN 为准确 HTTPS 源地址（不带尾斜杠），通过 HTTPS 反向代理运行。默认仅监听 127.0.0.1。
- 数据库存于 .data/moyu.sqlite（及 WAL 文件），此目录与 .env 已忽略且不能通过网站下载。请备份数据库，不要将其部署到无持久化的临时目录。没有自动将旧浏览器数据上传到服务器。

## 已实现

- 独立活动卡片页 activities.html：职业时光胶囊与代际回声，桌面双列、手机单列。首页导航「活动」及详情页「所有活动」均进入此页。
- 职业时光胶囊详情精简为排序、可选提醒邮箱、提交与折叠说明；只有填写邮箱时显示保存同意项，不填写也可参与。卡片以 compose=1 进入详情，有历史排序时可继续调整，不会直接跳过详情。
- 职业移动使用保留节点的 FLIP / Web Animations 换位动画（约 395—620ms）：主动卡片朱砂高亮，受影响卡片同步让位，顶部显示旧/新顺位。连续操作从当前视觉位置接续；排序数据立即更新，提交不依赖动画结束。减少动态效果时仅保留静态高亮和文字提示。
- 响应式首页：读墨、听愚、众说、品牌介绍。
- 普通访问、刷新及浏览器恢复首页时播放序章；从账号页登录、注册、保存资料或手动返回首页时跳过本次序章。支持跳过、Esc、重播及减少动态效果设置。
- 文章分类、全文搜索、带独立 hash 地址的阅读弹窗、浏览器前进后退支持。
- 文章书签与议题选择保存在本地浏览器；存储不可用时明确提示。
- 书单下载、素材说明、移动导航、键盘焦点、原生无障碍对话框。
- 5 篇文章与 2 篇播客文字样稿。没有假音频、虚假订阅量或虚假投票统计。

## 活动 Demo（第二版）

- 首页第一屏为职业时光胶囊，次入口为代际回声，点击进入独立页面。原有开场动画保留。
- capsule.html：8 种职业，桌面拖动和上下移动按钮（键盘、移动端均可操作）；提交前不展示榜单，提交后展示个人排序与汇总预测图表。不再展示模拟参与者逐条排序，6 份模拟数据仅用于计算汇总榜。均值相同者并列；低均值代表更早被替代的主观预测。
- 邮箱可选，保存需显式同意；仅存于 localStorage，不上传、不公开、不发送邮件。结果页可删除邮箱、删除整个胶囊、调整排序及生成不含邮箱的结果链接。重复提交替换旧记录，不重复计票。
- generations.html：分为 10后/20后（2010 年及以后）、90后/00后（1990—2009）、80后及以前（1989 年及以前）。两种模式都先选择本人的年龄段。
- 自己作答：完成 4 题后一次性提交；每台设备只计最新的一份回答，修改年龄段会从旧组移走那一票。
- 猜答案：4 题轮流指定其他两个年龄段，以开局锁定的该组票数中众数选项为正确答案；并列最多都算对，无票不计分；猜测不增加答案票数；揭晓后锁定选项并显示分布与逐题结果。
- 所有模拟票数在 activity-data.js 中，每个题目每组 40 票，绝非真实调查。正式题库可替换 questions 数组；每题使用稳定 id、四个选项及明确标注来源的统计。
- 持久化键：moyu:activity:capsule-v1、moyu:activity:answers-v1。与旧书签、观点数据相互独立；存储不可用时明确提示仅本次会话保存。

### 结果图表与链接分享（第三版）

- 众人预测榜默认展示横向柱状图，按平均顺位升序排列。图中「提前分」= 9 − 平均顺位（1—8 分），零基线和固定 0—8 刻度；柱越长表示越被认为更早被替代，不是概率或年份。表格作为可展开的精确数值补充。
- TXT 胶囊导出已移除。结果链接形如 `capsule.html?result=v1.01234567&author=用户名`；包含八个职业的排列和公开用户名，不包含邮箱、登录账号、用户 ID、头像、密码或封存时间。旧的无 author 链接显示「匿名访客的排序」。v1 字典固定，后续扩充职业需新增版本，不能改变旧字典含义。
- 接收方无需本地记录或登录即可还原只读结果页。共有图表按 6 份固定模拟排序 + 分享者 1 份计算，不混入接收者的本地胶囊，也不因访问重复计票。演示种子后续调整时，榜单可能随之改变；链接固定的是个人排序，不是历史统计。
- 「我也来排序」进入 `?compose=1`，从自己的旧排序或默认排序开始，不能把收到的预测直接当作自己的提交。浏览器前进后退与刷新都保留正确页面语义。
- 分享支持 Clipboard API；权限被拒时选中只读链接，允许手动复制。设备支持 Web Share API 时展示系统分享按钮，并处理取消、错误反馈。系统菜单是否提供微信由设备决定，网页不能直接替用户发送。
- 微信入口提供复制后在微信聊天粘贴的说明；微信内可尝试通过右上角菜单转发结果页。自定义微信卡片、封面和分享菜单需公众号 JS-SDK、合法域名及服务端签名，当前未接入。
- localhost、127.0.0.1、file 和私网地址显示显著警告，不能宣称好友可在公网访问。请先部署到可公开访问的 HTTPS 站点，再在公开地址生成分享链接；不硬编码或自动创建公开托管服务。
- 链接是可公开转发、可人为修改的普通快照，不加密、不认证、无撤回功能。本地删除或后续更改不会影响已发出的链接。链接解析严格拒绝重复 query 参数、重复职业、未知版本和无效排列。

### 账号、头像与署名（含第六版邮箱验证升级）

- 所有页面顶部增加账号入口。account.html 注册必须先验证邮箱，注册成功时服务端创建账号与登录会话；不再要求重复登录，直接返回进入账号页前的页面。普通登录成功也返回网站。
- 登录支持两种方式：① 完整邮箱 / 登录账号 / 用户名 + 密码；② 已注册邮箱 + 登录验证码（无需密码）。邮箱不区分大小写，不支持只输入 @ 前的邮箱前缀。若一个名字匹配多个账号，要求改用唯一注册邮箱，不任意选一个用户。
- `/api/auth/code` 接收 purpose=register/login（兼容旧请求默认 register）；验证码与邮箱、用途绑定。注册码不能登录，登录码不能注册；同用途新码作废旧码，发送频率限制跨用途共享。未知邮箱的登录发码返回通用提示，不发送邮件、不创建账号。`/api/auth/login-code` 一次性消费正确登录码并创建同样的 HttpOnly 会话。
- 数据库升级自动给旧 challenges 表增加 purpose 字段，已有验证码默认仍为注册用途；不删除已有账号或资料。前端切换登录方式会清空当前验证码挑战，避免混用。
- 资料保存先等待服务端确认，成功后立即返回原页面并更新用户名/头像；失败时停留，保留未保存的修改。跳转前清除未保存提示标记，避免 beforeunload 阻拦。
- 账号页返回首页时添加一次性 accountReturn=1 标记，首页在调用序章前消费并清除，保留原有查询参数和锚点。不会永久关闭序章，也不依赖浏览器存储；正常刷新与手动重播继续有效。
- 邮箱验证码由服务端生成六位随机数，10 分钟有效，60 秒重发间隔，每邮箱每小时最多 5 次、每来源 IP 每小时最多 10 次发送。错误 5 次锁定该验证码；成功注册后一次性消耗。新码成功发送后旧码作废；更改邮箱必须重新发送。验证码不返回前端、不写日志、不提供读取接口。
- 会话令牌随机生成，数据库仅存摘要；Cookie 为 HttpOnly / SameSite=Lax / 7 天有效，HTTPS 部署带 Secure。写入请求检查精确 Origin，静态文件服务使用白名单，密码通过 scrypt 加盐派生后保存。上线前仍需安全审计、全局防滥用、监控与备份。
- 登录账号 handle 为 1—64 个字符，允许中文（去除首尾空格、英文字母不区分大小写，不接受控制字符）；公开用户名为 1—24 个文字、数字、空格、点、横线或下划线。用户名不等于登录账号。结果小字只显示「用户名的排序」，无额外后缀；游客和旧链接使用「匿名访客的排序」。
- 注册密码：仅检查 8—128 位长度，不限制字符组合，纯数字、纯字母、符号都允许；不裁剪或改变密码。
- 资料修改影响之后生成的链接；已分享链接保留原有 author。接收方不得用自己账号的名字替换分享者名字。author 做长度/字符校验并 HTML 转义，但链接仍是可编辑的 Demo，不具备身份认证能力。
- 支持 JPG / PNG / WebP 头像上传、更换、恢复文字头像及四种底色。最大 5MB，长边不超过 4096px，居中裁切压缩成 192×192 JPEG 后提交本站服务器；不写入分享链接，不保留源图 EXIF。
- 旧版本地账号和答案未删除，也不自动转成已验证账户；需验证邮箱重新注册。原 localStorage 数据不能作为服务端身份依据，不尝试跳过邮箱验证做隐式迁移。密码找回与微信授权尚未提供。
- 登录后的职业/代际记录使用 `moyu:activity:user:<id>:<key>` 与游客隔离，不将游客的排序自动归给登录用户。旧书签、首页议题选择仍为设备级数据，不属于账号同步范围。
- 微信登录展示禁用的「待接入」入口与说明，不生成虚假授权二维码。正式接入需微信开放平台网站应用、已获授权的回调域名、服务端 code 换 token 和用户身份绑定、一次性 OAuth state 校验；AppSecret 不能放进前端。实际支持范围需按网站应用/公众号类型分别配置。
- returnTo 只允许同源的现有首页/活动页，防止开放重定向。存储写入失败不会宣称保存或注册成功。

### 正式上线前需要

1. 活动统计服务端持久化、防刷、隐私与未成年人保护策略。当前本地活动记录不能代表多个真实用户。
2. 配置真实 SMTP、验证投递、补全账号删除/密码找回与隐私流程。注册验证码不代表已接入职业提醒邮件，不能自动转成营销名单。
3. 公布「职业被替代」的地区、时间和证据阈值；人工审核后才允许触发提醒。任务自动化不等于职业消失。
4. 用服务端真实答题统计取代模拟样本，并记录猜题时的统计版本，避免答案随投票变化而改判。

### 测试

`npm run test:motion` 验证双卡片同步移动、DOM 身份/焦点、动画中途反向或连续操作、跨多项拖动、手机键盘、减少动态效果与动画中提交清理。
`npm test` 检查排序、并列名次、众数判分、无票以及年龄段迁移计票。
`npm run test:browser` 使用 Playwright Chromium 测试导航、拖动、表单、持久化、代际完整流程和 375—1440px 布局。需先启动本地预览服务，浏览器安装命令为 `npx playwright install chromium --no-shell`。测试在隔离浏览器中运行，不会删除用户当前浏览器的数据。截图保存在 test-results（不参与部署）。
`npm run test:share` 验证横柱数值、分享链接隐私、隔离浏览器恢复、已有胶囊不被覆盖、参与入口、坏链接恢复、复制降级和移动布局；原生分享 API 用模拟实现覆盖成功/取消分支，不等同于真实微信发送验证。
`npm run test:account` 创建隔离的内存 SQLite 和测试邮件接收器，验证邮箱绑定、过期、5 次错误、重发作废、验证码重放、用途隔离、邮箱/账号/用户名密码登录、验证码登录、重名处理、注册自动会话、Cookie、Origin、限流、私有文件保护、未配置/失败邮件反馈，以及注册/资料保存返回、头像更新和手机布局。不会发送真实邮件，也不测试微信 OAuth。
